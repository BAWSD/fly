## 二、从 GitHub 克隆后的准备工作（必读 ⚠️）

从 GitHub 拉取项目后，**不能直接启动**，需要先完成以下配置修改。

### 2.1 数据库密码配置

项目默认数据库密码为 `123456`，你需要修改为你自己的 MySQL 密码。

**需要修改的文件（共 5 个位置）：**

| 文件 | 修改位置 |
|------|---------|
| `deploy/mysql-redis/docker-compose.yml` | `MYSQL_ROOT_PASSWORD: 123456` |
| `flight-info-service/src/main/resources/application.yml` | `password: 123456` |
| `flight-status-service/src/main/resources/application.yml` | `password: 123456` |
| `airport-map-service/src/main/resources/application.yml` | `password: 123456` |
| `data-collector-service/src/main/resources/application.yml` | `password: 123456` |

> 🔧 **建议**：全局搜索 `123456` 替换为你的密码，或搜索 `password` 逐一修改。

### 2.2 百度地图 AK 配置

项目前端使用了百度地图，需要你自己申请百度地图密钥。

**申请地址：** https://lbsyun.baidu.com/apiconsole/key

**需要修改的文件（共 2 个）：**

| 文件 | 修改项 | 默认值 |
|------|--------|--------|
| `flight-tracking-frontend/.env.development` | `VITE_BAIDU_MAP_AK=你的百度地图AK` | 开发环境 |
| `flight-tracking-frontend/.env.production` | `VITE_BAIDU_MAP_AK=你的百度地图AK` | **生产构建必须填写，不能为空** |

> ⚠️ `.env.production` 原本为空值，已补全默认占位值。使用 `npm run build` 构建生产版本前必须替换为有效的百度地图 AK。

### 2.3 Nacos 配置

每个微服务都已配置为通过 Nacos 进行服务注册与发现，**仅注册发现，未启用配置中心**（`config.enabled=false`），所以你不需要额外配置 Nacos 配置项。

- Nacos 地址统一为 `localhost:8848`
- 各服务启动后会自动注册到 Nacos

### 2.4 端口说明

| 组件 | 端口 | 说明 |
|------|------|------|
| MySQL | 3306 | Docker 容器 |
| Redis | 6379 | Docker 容器 |
| Nacos | 8848 | Docker 容器 |
| API Gateway | 18080 | 后端网关（前端代理目标） |
| flight-info-service | 8081 | 航班信息微服务 |
| flight-status-service | 8082 | 航班状态微服务（含 WebSocket） |
| airport-map-service | 8083 | 机场地图微服务 |
| data-collector-service | 8084 | 数据采集微服务 |
| AI 分析服务 | 5000 | Python Flask 服务（可选） |
| 前端 | 5173 | Vite 开发服务器 |

> ⚠️ 如果端口被占用，需修改对应服务的 `application.yml` 中的 `server.port`，同时同步更新 API Gateway 的路由配置和前端 `vite.config.js` 中的 proxy 配置。

## 三、启动基础设施（Docker 容器）

### 3.1 启动 MySQL + Redis

```bash
cd flight-tracking-platform/deploy/mysql-redis
docker-compose up -d
```

- MySQL: `localhost:3306`，用户名 `root`，密码见 2.1 节配置，如果端口被占用会启动失败，先以管理员身份启动powershell输入net stop MySQL80
- Redis: `localhost:6379`

### 3.2 启动 Nacos（服务注册与发现）

```bash
cd flight-tracking-platform/deploy/nacos
docker-compose up -d
```

- Nacos 控制台: `http://localhost:8848/nacos`
- 默认账号: `nacos / nacos`

### 3.3 初始化数据库与演示数据

项目根目录提供了 `init-all.sql` 一体化初始化脚本，**包含建库、建表、插入演示数据与轨迹数据**。

在 Docker 容器启动后执行：

```bash
# Windows（推荐：使用原始重定向，避免 PowerShell 编码导致中文变成 ???）
cmd /c "docker exec -i flight-mysql mysql -uroot -p123456 --default-character-set=utf8mb4 < init-all.sql"

# 或使用 MySQL 客户端直接连接
mysql -u root -p123456 --default-character-set=utf8mb4 < init-all.sql
```

> 🔧 如果修改过 MySQL 密码，请将 `123456` 替换成你自己的密码。
> 
> ⚠️ 不要用 `Get-Content ... | docker exec ...` 管道方式导入 SQL，否则可能发生编码转换，导致中文入库成 `???`。

**脚本执行后生产以下数据：**

| 数据库 | 表 | 数据量 | 说明 |
|--------|-----|-------|------|
| `flight_info` | `flight_info` | 22 行 | 航班基础信息（含国内/国际航线、6 种状态） |
| `flight_status` | `flight_status` | 22 行 | 航班实时状态（含坐标、速度、高度） |
| `airport_map` | `airport_info` | 15 行 | 国内外机场信息（含经纬度、时区） |
| `flight_data` | `collected_flight_data` | 0+ 行 | 数据采集表（由 data-collector 自动写入） |

> 💡 `init-all.sql` 以 `INSERT IGNORE` 方式插入数据，重复执行不会产生重复记录。
> 
> 如果首次 Docker 启动已通过 `deploy/mysql-redis/mysql/init/` 自动完成建表，`init-all.sql` 仍可安全运行 —— 仅补充插入演示数据。

## 四、启动后端微服务

> 先 Maven 编译打包（确保代码无误）

```bash
cd flight-tracking-platform
mvn clean install -DskipTests
```

> 然后按 **以下顺序** 分别启动 5 个服务（每个服务单独开一个终端）

### 服务 1：API Gateway（网关，端口 18080）

```bash
cd flight-tracking-platform
mvn spring-boot:run -pl api-gateway
```

### 服务 2：航班信息服务（端口 8081）

```bash
cd flight-tracking-platform
mvn spring-boot:run -pl flight-info-service
```

### 服务 3：航班状态服务（端口 8082，支持 WebSocket）

```bash
cd flight-tracking-platform
mvn spring-boot:run -pl flight-status-service
```

### 服务 4：机场地图服务（端口 8083）

```bash
cd flight-tracking-platform
mvn spring-boot:run -pl airport-map-service
```

### 服务 5：数据采集服务（端口 8084）

```bash
cd flight-tracking-platform
mvn spring-boot:run -pl data-collector-service
```

### 服务 6（可选）：AI 分析服务（Python，端口 5000）

```bash
cd flight-tracking-platform/ai-analysis-service
pip install -r requirements.txt
python app.py
```

> 可用 `netstat -ano | findstr "18080 8081 8082 8083 8084"` 验证服务是否启动成功。

## 七、架构说明

```
用户浏览器 (localhost:5173)
      │
      │ proxy /api/* → localhost:18080
      ▼
API Gateway (端口 18080) —— 注册到 Nacos
      │
      ├── /api/flight/info/**   →  flight-info-service (8081)
      ├── /api/flight/status/** →  flight-status-service (8082)
      ├── /ws-flight/**        →  flight-status-service (WebSocket)
      ├── /api/airport/**      →  airport-map-service (8083)
      ├── /api/collector/**    →  data-collector-service (8084)
      └── /api/ai/**           →  AI分析服务 (localhost:5000)
```

### 各服务注册到 Nacos（localhost:8848）

## 八、排错指南

### 8.1 服务启动报 "No data source" 或数据库连接失败
- 检查 MySQL 是否已启动: `docker ps | findstr mysql`
- 检查数据库连接地址: `localhost:3306`
- **检查用户名密码**：是否已在 6 个配置文件中修改为你的密码？

### 8.2 微服务启动报 Nacos 连接失败
- 检查 Nacos 是否已启动: `docker ps | findstr nacos`
- 检查 Nacos 控制台: `http://localhost:8848/nacos`

### 8.3 API Gateway 路由不生效
- 确认微服务**全部注册到 Nacos**（查看 Nacos 控制台服务列表）
- 检查 Gateway 配置中的路由路径匹配

### 8.4 前端页面白屏或接口报错
- 打开浏览器开发者工具 → Network 标签
- 检查请求 URL: 应代理到 `http://localhost:18080`
- 检查 vite.config.js 中 proxy 配置是否正确
- **检查百度地图 AK** 是否已填写正确的密钥

### 8.5 端口冲突
- 如果 5173 被占用，Vite 会自动切换到 5174 等
- 如果后端端口冲突，修改对应 `application.yml` 中的 `server.port`
- 同时更新 API Gateway 的路由配置和前端 proxy 配置

### 8.6 Maven 编译报错
- 尝试先跳过测试编译: `mvn clean install -DskipTests`
- 检查 Java 版本是否为 11+

## 九、一键启动脚本

项目根目录提供了 `start.ps1` 一键启动脚本，可自动完成基础设施、数据库初始化、后端服务与前端启动。

项目在 `flight-tracking-platform/deploy/start-all.ps1` 中提供了 PowerShell 一键启动脚本，可以自动完成全部启动流程。

> ⚠️ **使用脚本前，请确保已完成第二章的全部配置修改！**

### 使用方式

**方式 A（推荐）**：在项目根目录运行 `start.ps1`

```powershell
cd course1
powershell -ExecutionPolicy Bypass -File .\start.ps1
```

> 如果提示权限不足，建议以管理员身份运行 PowerShell。

**方式 B（旧脚本）**：使用 `flight-tracking-platform/deploy/start-all.ps1`

在项目根目录（`course1`）下，右键点击 `flight-tracking-platform/deploy/start-all.ps1` → **"使用 PowerShell 运行"**，或打开 PowerShell 执行：

```powershell
cd flight-tracking-platform/deploy
.\start-all.ps1
```

### 脚本自动完成的内容

| 步骤 | 操作 | 说明 |
|------|------|------|
| 0 | 前置环境检查 | 检查 Docker、Maven、Node.js、npm、Python 是否安装；检查关键端口是否被占用；检查各服务 Nacos 地址配置是否正确 |
| 1 | 启动基础设施 | 创建 Docker 网络 → 启动 Nacos（8848）→ 启动 MySQL（3306）+ Redis（6379），等待 30 秒 |
| 2 | 构建 common 模块 | `mvn -pl common -am install -DskipTests` |
| 3 | 启动 API Gateway | 在弹窗中启动网关（端口 18080），等待 15 秒 |
| 4 | 启动后端微服务 | 依次启动 flight-info-service(8081)、flight-status-service(8082)、airport-map-service(8083)、data-collector-service(8084) |
| 5 | 启动 AI 分析服务 | 安装 Python 依赖，启动 AI 服务（端口 5000） |
| 6 | 启动前端 | `npm install` → `npm run dev`（端口 5173） |

### 注意事项

- ⚠️ **首次运行前**：必须完成第二章的所有配置修改：
  - 6 个位置的数据库密码改为你自己的密码
  - 百度地图 AK 替换为你自己的密钥
- ⚠️ **建议以管理员身份运行 PowerShell**，避免因权限不足导致 Docker 操作失败
- ⚠️ **由于脚本会弹出多个命令行窗口**，建议在桌面环境运行，而非远程 SSH
- ⚠️ **停止服务**：关闭对应的 PowerShell 窗口即可，或手动执行 `docker-compose down` 停止 Docker 容器

### 一键启动 vs 手动启动

| 对比项 | 一键启动脚本 | 手动启动 |
|--------|------------|---------|
| 操作复杂度 | 一条命令 | 需要开 7+ 个终端 |
| 输出可视性 | 隐藏窗口运行 | 每个服务独立窗口 |
| 排错便利性 | 需查看各窗口 | 直接看到日志 |
| 适用场景 | 快速验证、演示 | 开发调试、排查问题 |

> 💡 **推荐**：日常开发使用**手动启动**便于排错；演示或快速验证使用**一键启动脚本**。
